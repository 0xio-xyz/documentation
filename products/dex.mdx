## Overview

**0xio DEX** is a **cross-chain swap protocol** that enables users to swap native tokens across chains — starting with **OCT ↔ ETH** between Octra and Ethereum Sepolia. The protocol uses a **solver-based architecture** with on-chain escrow and oracle verification.

## How It Works

### OCT → ETH

<Steps>
  <Step title="Connect Wallets">
    Connect your 0xio wallet (Octra) and MetaMask (Sepolia)
  </Step>
  <Step title="Get Quote">
    Enter the OCT amount — the solver provides a real-time quote with TWAP pricing
  </Step>
  <Step title="Lock OCT">
    OCT is locked in the SwapVault contract on Octra with a minimum receive commitment
  </Step>
  <Step title="Solver Fills">
    The solver detects the lock, sends ETH to your Sepolia address (~30s)
  </Step>
  <Step title="Oracle Attests">
    The oracle independently verifies the ETH was sent and attests on-chain
  </Step>
  <Step title="Settlement">
    After a challenge window, the solver claims the locked OCT
  </Step>
</Steps>

### ETH → OCT (Commit-Then-Fill)

<Steps>
  <Step title="Connect Wallets">
    Connect MetaMask (Sepolia) and 0xio wallet (Octra)
  </Step>
  <Step title="Lock ETH">
    ETH is locked in the EthEscrow contract on Sepolia
  </Step>
  <Step title="Solver Commits">
    The solver calls `fill()` on the escrow to reserve the order (no OCT sent yet)
  </Step>
  <Step title="Solver Sends OCT">
    Only after `fill()` confirms on Ethereum, the solver sends OCT on Octra
  </Step>
  <Step title="Oracle Attests + Settlement">
    Oracle verifies, solver settles, receives the locked ETH
  </Step>
</Steps>

<Info>
The **commit-then-fill** pattern ensures the solver never sends OCT before the escrow commitment is confirmed on Ethereum. This eliminates the risk of the solver losing funds if the fill transaction fails.
</Info>

## Features

- **Cross-Chain Swaps**: OCT ↔ ETH between Octra and Ethereum Sepolia
- **TWAP Pricing**: 5-minute time-weighted average prices from CoinGecko + DexScreener
- **On-Chain Rate Protection**: `min_receive` committed at lock time — solver can't underpay
- **Slippage Control**: Configurable slippage tolerance (0.5%, 1%, 2%, custom)
- **Liquidity Display**: Real-time solver balance shown before swap
- **Network Detection**: Auto-prompts MetaMask to switch to Sepolia

- **Price Chart**: Live OCT/USD sparkline on the swap page

## Security

The protocol is built around a layered defense model: at no point can the solver underpay or the user lose locked funds.

### 5-Layer Defense

| Layer | Protection |
|-------|-----------|
| **Solver Bond** | 20K OCT staked as collateral, slashed on fraud |
| **On-Chain Rate Commitment** | `min_receive` prevents solver from underpaying |
| **Oracle Verification** | Independent fill verification before attestation |
| **Challenge Window** | Dispute period after attestation, before the solver can settle |
| **Stale Fill Refund** | User reclaims funds if oracle doesn't attest within timeout |

### Key Security Properties

- **Commit-then-fill**: Solver calls `fill()` on escrow BEFORE sending destination tokens — zero solver risk
- **Fee snapshot**: Fee rate locked at swap time, can't be changed retroactively
- **Reentrancy guard**: All ETH transfer functions protected
- **Emergency refund**: Owner can refund unfilled swaps (blocked after fill)
- **Reconciliation**: Solver auto-reconciles DB vs on-chain state every 5 minutes

## Architecture

```
User (0xio Wallet + MetaMask)
    │
    ▼
Frontend (dex.0xio.xyz)
    │
    ├── Quote: Solver API (solver.0xio.xyz)
    │     └── TWAP pricing from Oracle (oracle.0xio.xyz)
    │
    ├── OCT→ETH: SwapVault v7 (Octra) → Solver sends ETH (Sepolia)
    │
    └── ETH→OCT: EthEscrowV2 (Sepolia) → Solver sends OCT (Octra)
```

### Swap Lifecycle (OCT → ETH)

```
lock() → fill() → attest() → [challenge window] → settle()
  │        │         │                                │
  │        │         │                                └── Solver gets OCT
  │        │         └── Oracle verifies ETH was sent
  │        └── Solver sends ETH + posts dest tx hash
  └── User locks OCT with min_receive commitment
```

### Swap Lifecycle (ETH → OCT)

```
lock() → fill() → send OCT → updateFill() → attest() → settle()
  │        │         │            │              │           │
  │        │         │            │              │           └── Solver gets ETH
  │        │         │            │              └── Oracle verifies
  │        │         │            └── Post real Octra tx hash
  │        │         └── Safe: fill is confirmed on Ethereum
  │        └── Solver commits on escrow (no OCT sent yet)
  └── User locks ETH in EthEscrowV2
```

## Solver API

### GET /api/quote

Get a swap quote with current TWAP pricing.

```
GET https://solver.0xio.xyz/api/quote?from=OCT&to=ETH&amount=100
```

Response includes: rate, receive amount, fee, liquidity availability, intent hash.

### GET /api/swaps

List recent swaps with status tracking.

### GET /api/chains

Supported chains/tokens plus the live contract addresses (SwapVault, EthEscrow) and solver/treasury wallets. The DEX frontend reads contract addresses from this endpoint at runtime.

### GET /api/health

Solver status: RPC connectivity, bond amount, liquidity on both chains.

### GET /api/price

Proxied oracle price feed (no API key needed from frontend).

## Refund Mechanisms

| Scenario | Mechanism |
|----------|-----------|
| Solver never fills | User calls `refund()` once the lock expiry passes |
| Solver fills but oracle never attests | User calls `refundStaleFill()` after the stale-fill window |
| Emergency | Owner calls `emergencyRefund()` — immediate, unfilled swaps only |
