0xio implements industry-standard cryptographic algorithms to ensure the highest level of security for your assets.

## Signing Algorithm

**Ed25519** (Twisted Edwards Curve)

- High-speed signature generation and verification
- 256-bit security level
- Implemented via TweetNaCl.js for browser compatibility
- Resistant to side-channel attacks

## Hashing

- **SHA-256:** Primary hashing algorithm for address generation
- **HMAC-SHA512:** Used in key derivation processes

## Symmetric Encryption

**AES-GCM (256-bit)** for local vault protection

- Authenticated encryption mode
- Protects your encrypted keys on device
- Ensures data integrity and confidentiality

## Key Derivation

### Mnemonic Standard

**BIP39** - 12 or 24-word recovery phrases

- Standard: 12-word phrases (128-bit entropy)
- Extended: 24-word phrases (256-bit entropy)
- Dictionary: 2048 words from official BIP39 wordlist

### Seed Generation

**PBKDF2-HMAC-SHA512** with 2048 iterations

- Password-based key derivation function
- Converts mnemonic to cryptographic seed
- Salt: Configurable passphrase (optional)

### Master Root Key Derivation

All 0xio platforms (extension, mobile, desktop) use the same canonical key derivation:

```
master_key = HMAC-SHA512("Octra seed", seed)[0:32]
```

- **Deterministic:** The same seed phrase always produces the same master key
- **Cross-platform:** Importing the same seed phrase produces the same address on all 0xio products
- **Secure:** HMAC-SHA512 provides cryptographic strength; only the first 32 bytes are used as the Ed25519 private key

## Address Format

0xio generates Octra addresses through a multi-step process:

<Steps>
  <Step title="Generate Ed25519 Public Key">
    Derive public key from private key using Ed25519
  </Step>
  <Step title="Hash Public Key">
    Compute SHA-256 hash of the public key
  </Step>
  <Step title="Base58 Encoding">
    Encode the hash using Base58
  </Step>
  <Step title="Add Prefix">
    Prefix with `oct` for Octra Network identification
  </Step>
</Steps>

**Result:** A 47-character string (e.g., `oct1abc123def456ghi789jkl012mno345pqr678stu901`)

## Privacy Cryptography (PVAC)

0xio implements PVAC (Privacy Via Additive Ciphers), a custom privacy system built on fully homomorphic encryption. All PVAC operations are performed locally on your device using **pvac-rs**, a purpose-built Rust cryptographic library.

### Core Operations

1. **FHE Encrypt/Decrypt:** Additively homomorphic encryption of token amounts — encrypted values can be added on-chain without decryption
2. **Range Proofs:** Zero-knowledge proofs (64-bit) proving an encrypted amount is non-negative and within bounds, without revealing the value
3. **Pedersen Commitments:** Binding commitments to amounts using elliptic curve points, used for transaction integrity
4. **Stealth Transfers:** ECDH key agreement generates one-time stealth addresses for unlinkable private sends
5. **Zero Proofs:** Proof that a ciphertext encrypts zero, used during decrypt (withdrawal) operations

### pvac-rs

The **pvac-rs** library compiles to multiple targets to run natively on each platform:

| Platform | Target | Performance |
|----------|--------|-------------|
| Extension | WebAssembly (rayon multithreading) | ~80s range proof |
| Desktop | Native Rust binary | ~17s range proof |
| iOS | Static library (aarch64) | ~59s range proof |
| Android | Shared library (arm64, armv7, x86_64) | ~103s range proof |

**Key dependencies:** `curve25519-dalek` for elliptic curve arithmetic, `@noble/hashes` for PBKDF2/SHA-256/HMAC.
